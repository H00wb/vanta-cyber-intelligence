4. SUNUCUDA GERÇEK KAYDI GÖR
Yerel tarayıcı otomasyonunun kaydı için scripts/verify-local-record.mjs yukarıda bağımsız D1 kontrolü yapar. Kendi manuel kaydını kontrol etmek için Network/ekrandan UUID'yi al ve şu komutu UUID yerine gerçek test kimliği yazarak çalıştır:
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --command "SELECT id,name,email,service,description,created_at FROM service_requests WHERE id='UUID'"
Beklenen: tam bir satır, dört alan form ile aynı, sunucu created_at dolu. local flag canlı veritabanını sorgulamaz.
Sunucuyu durdurup tekrar npm run dev ile başlat, aynı SELECT'i tekrarla. Satır korunmalı. Yalnız sayfayı yenilemek kalıcı sunucu kaydının kanıtı değildir.
Canlı kayıt için Sites > Site ayarları > Database görüntüleyicisinde DB / service_requests tablosunu aç. evidence/production-verification.json içindeki UUID ile gerçek satırı karşılaştır. Değerlendiriciye veritabanı yetkisi vermek yerine yalnız kurgusal satırın kanıtını paylaşabilirsin. Ziyaretçilere kayıtları okutan bir endpoint yoktur.

6. SUNUCU DOĞRULAMASINI ATLATMAYI DENE
Tarayıcı doğrulamasını değiştirmek sunucu kurallarını aşamaz. Otomatik tests/request.test.mjs ve e2e/site.spec.ts doğrudan POST ile bunu sınar. İstersen yerel sayfada DevTools Console'da kurgusal örneği çalıştır:
  fetch('/api/requests', {method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({name:'Deniz Örnek',email:'gecersiz',service:'bilinmeyen',description:'kısa',requestId:crypto.randomUUID()})}).then(async r => console.log(r.status, await r.json()))
Beklenen: 422 ve alan hataları. Yeni kayıt oluşmaz.
Bozuk JSON → 400; yanlış Content-Type → 415; 16 KiB üstü gerçek gövde → 413; farklı Origin → 403; GET → 405. Bunlar Node suite'te ayrı senaryolardır.

7. GÖNDERİLİYOR / ÇİFT TIK / TEKRAR GÖNDERİM
